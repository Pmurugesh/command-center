# Command Center + OpenClaw audit — 2026-09-14

Read-only audit of the dashboard (this repo), the operations data it renders, the OpenClaw
fleet on the mini, the scripts that glue them, and the context every agent is fed. Five
parallel sub-audits plus direct checks against the live mini (`/api/system`, launchd, logs,
session transcripts). Every number below was measured; where a claim could not be verified
it says so.

## Verdict

The machine has out-built the business. It commits 20 times a day, sends ~105 Telegram
messages a week, and burns about half its model spend to say "nothing changed" — around a
sales motion with one live conversation (OEIS), one overdue proposal (CDT, 47 days), an
unpriced product, and a Phase-1 campaign that will miss on 2026-09-22 without any surface
saying so. The dashboard's biggest defect is not a bug; it is that "Automation healthy" and
"all green" are true of the cron scheduler and false of everything the founder cares about.

Three technical items are urgent regardless of the business question: a confirmed path
traversal that lets any request on the tailnet read every operations file and overwrite the
main agent's instruction file, multipart upload routes any website can post to as "Note
from Pavan", and the fact that nothing outside git on the mini (cron store, credentials,
agent memory, Keychain) is backed up anywhere.

## 4. Technical risk, ranked

### Critical

1. **Path traversal, confirmed.** `GET /api/bids/..%2Fintelligence` returned every intelligence file. `PUT /api/bids/<traversal>/status` writes `.status.json` anywhere; `PUT /api/crm/drafts/..%2F..%2Fagents%2Fmain%2FAGENTS` overwrites the main agent's instruction file and commits it, which the janitor then propagates. `src/lib/files.ts:101,166,176`, `src/lib/followup.ts:64,262,321`. `safeSlug` exists in `crm.ts:71` and is simply not applied on these routes.
2. **CSRF into the agent.** `/api/intake`, `/api/bids`, `/api/bids/[bidName]/documents` accept multipart (no preflight), check no `Origin`/`Sec-Fetch-Site`, and `intake.ts:63-84` runs `openclaw agent --agent main --message "Note from Pavan: …"`. Any web page open on a tailnet device can put words in Pavan's mouth to Paladin.
3. **No backup of anything outside git.** Time Machine: no destination. Unrecoverable on disk loss: the live cron store (`state/openclaw.sqlite`, 13 jobs, only 4 have installers), `openclaw.json`, 9 Keychain items, `qual-table.env`, every `agents/*/memory/` (gitignored, including all six `lessons-learned.md`), 88 staged emails, ledgers. Anthropic API key sits in plaintext in five `auth-profiles.json.sqlite-import.*.bak` files.

### High

4. **Deploy has no memory and no rollback.** A failed `pnpm build` is overwritten by `state: current` on the next 5-minute tick because HEAD already equals origin/main (`deploy-on-merge.sh:63-67`); the build never retries and heartbeat reports the deploy healthy. The build runs in the live `.next` while `next start` serves from it; a crash after a failed build loops on "Could not find a production build".
5. **Dashboard bound to `0.0.0.0`.** Tailscale Serve proxies to 127.0.0.1, so the wide bind buys nothing and exposes 14 unauthenticated mutating routes (including cron run and agent trigger) to the LAN.
6. **False greens, one layer up from the fixed ones.** `page.tsx:66-79` swallows 14 of 15 data-source failures into empty arrays without logging; `cron/[id]/run` returns `success:true` when `openclaw` exits 1; heartbeat's email-sync probe can never parse the log format (`^(\S+)` needs an ISO date nothing writes) so it reports "late 16,687,524 hours" forever; the janitor that keeps the mini and GitHub in sync is monitored by nothing.
7. **Concurrent unlocked writers.** `roadmap-check.ts:903` plain `writeFile` from three launchers (5-min watcher, 08:00 cron, Rescore button) under a janitor doing `git add -A` every 120s; dashboard `.status.json` writes (`files.ts:176-189`) unlocked while bid-sync holds a lock; `index.lock` collisions drop semantic commits silently (`shell.ts:47-49`).

### Medium

8. **Read amplification.** One Today render: ~1,000 file opens, ~7 MB, ~20 process spawns; `listBids` 5×, `listContacts` 4×, agent activity re-reads 112 alerts per agent; `/api/system/health` polled every 30s reads every report to count them. Zero caching in `src/lib`. Calendar fetch has no timeout and gates the render.
9. **Quality gaps.** `scripts/` excluded from `tsc` and red (3 errors); no test runner (125 ad-hoc `node:test` cases pass but are not in `package.json`); 29 silent catch-alls; `rehype-raw` with no sanitizer on agent-scraped markdown; 8 routes return `String(error)`; unvalidated JSON reaches git-backed stores (a non-date `date` makes a contact immune to going cold).
10. **OpenClaw drift.** Mini runs 2026.6.34; 2026.9.4 is current with Opus 5 support merged. `memory-core` is dead (provider openai, no key, 0/25 files indexed, vector search paused) while granola-sync is granted `memory_search`. Gateway stderr goes to `/dev/null`. Session archive 97 MB, never pruned. Two agentTurn crons exist only to wrap `research-scan.sh`, which pipes into `claude -p` and has been SIGKILL'd 4 weeks running. A lesson in main's memory says "tokens are covered by the Max plan" — the fleet is on a metered API key.
11. **Scripts.** `sync-email.py` fetches every body in the 30-day window every 15 minutes before deduping; caleprocure exit 3 ("site asked us to stop") is not acted on; `caleprocure`/`lead-sync`/`bid-sync` declare 1–24h cadences in `heartbeat.ts` and fire at 61–72h; the unhardened MacBook janitor is still the copy this repo's README installs; no log rotation anywhere; Tailscale node key expiry is documented as "~Sept 2026" — verify it is disabled in the admin console.

### What is actually good

`execFile` with arg arrays everywhere (no shell injection found); `store.ts` locking and atomic writes are correct where used; the cron false-green at the shell/health layer is genuinely fixed; `src/lib/dates.ts` documents its footgun properly; CI runs typecheck, lint, tests and `bash -n`; the scribe gate does what it claims (0 tokens when nothing is staged); granola-sync is the best-written cron prompt in the fleet; `USER.md`'s email-voice section is the single best piece of founder context in the system.
